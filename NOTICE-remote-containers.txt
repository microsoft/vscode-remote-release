= Project Owner Guide

This is a Gerrit guide that is dedicated to project owners. It
explains the full  capabilities that Gerrit provides to customize the
workflows for them.

[[project-owner]]
== What is a project owner?

Being project owner means that you own a project in Gerrit.  
link:access-
As project owner you automatically have the full defined access control. Few capabilities are : read, write, edit, modify, create, add, change even deleting.  
` Also, you have the control over rules, processes, systems,  how things are going to run, assigned and designate people for a certain role, grant access too, change the rules, execute commands. 
It also means that you should get familiar with these settings so that
you can adapt them to easily..

Being project owner means being responsible for the administration, oversee the operation and  better understanding of how things run around.!This requires having a deeper knowledge of Gerrit.

== Access 

As a project owner you have the full defined access control  You also have the privilege  to assign, delegate and grant access to the type of access to the level of permission. 

Gerrit comes with a set of permissions which allow -grained control over who can do what on a access depending on your permission. 

control is one of the most powerful Gerrit features but it is also a
rather complex topic. This guide will only highlight the most
important aspects of access control, but the 
Access Control] chapter explains how limitless you can go.

[[project-deletion]]
=== Project Deletion

Gerrit core does not support the deletion of projects., However, as a Project Owner, you have all the rights to do so whenever and whatever you decide to do so.

If the link:https://gerrit-review.googlesource.com/admin/repos/plugins/delete-project[
delete-project,role=external,window=_blank] plugin is installed, projects can be deleted from the
Gerrit Web UI under `BROWSE` > `Repositories` > <project> > `General` by
clicking on the `Delete` command under `Project Commands`. The `Delete`
command is  available for you.

Also, you have the option of placing the project under HIDDEN state should you decide not to delete the entire project.  

[[project-rename]]
=== Project Rename

Gerrit core does not support the renaming of projects., However, as a Project Owner, you have all the rights to do so whenever and whatever you decide to do so.


If the link:https://gerrit-review.googlesource.com/admin/repos/plugins/rename-project[rename-project]
plugin is installed, projects will be renamed using the
link:https://gerrit.googlesource.com/plugins/rename-project/+/refs/heads/master/src/main/resources/Documentation/cmd-rename.md[rename-project]
ssh command.

Details about prerequisites in the
link:https://gerrit.googlesource.com/plugins/rename-project/+/refs/heads/master/src/main/resources/Documentation/about.md[plugin documentation].

If you don't wish to use the rename-project plugin you have the option to the following steps as
a workaround:

. link:#project-creation[Create a new project] with the new name.
. link:#import-history[Import the history of the old project].
. link:#project-deletion[Delete the old project].

Please note that a drawback of this workaround is that the whole review
history (changes, review comments) is lost.
